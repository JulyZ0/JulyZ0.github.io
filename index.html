    平台组成

    多租户不是加个字段。

    从请求进网关到工具落地执行，租户身份一路带到底。下面每一项都是 Chiron 仓库里已经存在的模块，而不是路线图。

    租户上下文贯穿数据层

    租户隔离不止停在接口校验，数据库访问同样带租户上下文，避免一次漏判就跨租户读到数据。

    配额、限流与计费幂等

    租户级与用户级配额、按租户限流；计费写入幂等，重试不会重复扣费。邀请码与套餐支撑对外 SaaS 开通。

    审计与可回放证据链

    租户级审计记录思考、工具调用与用量，形成可回放的证据链，事后能还原一次运行到底做了什么。

    执行隔离是默认值

    工具执行下沉到独立的受限容器。沙箱不可用时拒绝启动，而不是悄悄降级成在主进程里跑。

    过程可见，断线可续

    思考、工具调用、用量都是独立事件；连接断开后带 Last-Event-ID 重连，从断点继续而不是重跑。

    多副本真的能扩

    会话锁、SSE 广播与回放、运行亲和路由让网关和引擎横向扩容后，同一个会话仍然落在正确的地方。

    技能与 MCP 插件

    内置目录型技能资产（{name}/SKILL.md），配合 MCP 接入外部工具，成员按需挂到自己的 Agent 上。

    知识库与多层级记忆

    知识库检索与多层级记忆在同一引擎内协同；向量直接存 PostgreSQL 的 float8[]，不依赖 pgvector 扩展。

    身份接入

    网关统一负责认证与路由，支持 SSO 接入企业既有身份体系，管理后台与业务请求走同一套权限判定。

    交付形态

    同一套代码，三种落地方式。

    切换下面的场景，看这套平台在不同交付方式下各自负责什么。

    一套实例服务全公司

    成员各自建 Agent、挂知识库与技能，管理员在一处统一管配额与审计。不需要为每个部门单独部署一套，也不用担心 A 部门的会话被 B 部门检索到。

    • 成员自助建 Agent，知识与技能按需挂载
    • 管理员集中掌握租户与用户配额
    • 租户级审计回答「这次运行用了什么数据」

    把 Agent 能力卖给外部客户

    租户隔离做到数据库层，计费写入幂等，邀请码与套餐负责开通，限流按租户生效。一个客户跑满配额不会把别的客户拖垮。

    • 数据库层带租户上下文，隔离不靠业务代码自觉
    • 计费幂等，网关重试不会重复扣费
    • 邀请码、套餐与按租户限流

    数据不出内网

    整套服务部署在客户内网，存储可用自建 RustFS 替代云端 S3。工具执行在独立受限容器里进行，沙箱不可达时服务拒绝启动，而不是降级执行。

    • Docker Compose 编排，存储可换成自建 RustFS
    • 工具执行下沉到独立受限容器
    • 沙箱不可用即拒绝启动，不静默降级

    架构

    三层职责，边界清楚。

    网关只做接入与治理，引擎只做推理与执行，前端只做交互。任何一层都可以单独扩容。

    1. 01 · 浏览器

      Vue 3 前端

      TypeScript + Vite 构建，经 Nginx 提供静态资源，通过 SSE 接收运行事件。

    2. 02 · 网关

      Go 网关

      认证、路由、限流、计费、管理后台与 SSE 转发。租户身份在这里确立并向下传递。

    3. 03 · 引擎

      Python AI 引擎

      对话、Agent、知识库、技能、记忆与 MCP。工具调用交给独立的沙箱服务执行。

    PostgreSQL

    业务数据与向量（float8[]），Alembic 管理迁移

    Redis

    会话锁、队列与事件广播

    S3 / RustFS

    文件与知识库原文存储

    沙箱服务

    受限容器内执行工具
